# Daymark — состояние лабораторной №7

## Что подготовлено в исходном проекте

- Одно приложение Android: Kotlin + XML Views, Room/SQLite, OkHttp + Gson.
- Debug-only сценарии Logcat, три исключения и демонстрация утечки Activity.
- Unit/JUnit, Mockito, Fake repository, Robolectric, MockWebServer.
- Room DAO, миграции 1→2→3, проверка идемпотентного повторного Sync.
- Espresso, Espresso Intents, IdlingResource, Page Object, Android Test Orchestrator.
- JaCoCo quality gate 70% для пакета domain.
- Macrobenchmark: холодный старт и прокрутка длинного списка.
- GitHub Actions и отдельный ручной workflow Firebase Test Lab.
- Runbook по 15 заданиям, чек-лист скриншотов и шаблон журнала дефектов.

## Статическая проверка комплекта в среде подготовки

- XML-файлы приложения: 21; синтаксически корректны при XML-разборе.
- JVM test annotations: 32; параметризованный тест имеет 5 входных вариантов, то есть ожидается 36 выполнений.
- Android instrumented test annotations: 10.
- Macrobenchmark-сценарии: 2.

## Что не может считаться выполненным без запуска Android Studio

Следующие результаты должны быть получены на твоём ПК и приложены к отчёту:

1. Gradle Sync, сборка debug APK и Android Lint.
2. Фактический запуск JVM и instrumented тестов.
3. HTML-отчёты JaCoCo и подтверждение порога 70%.
4. Реальные скриншоты Logcat, Debugger, Layout/Database/Network Inspector.
5. Результаты ручной матрицы устройств и Monkey.
6. Реальные CPU/Memory/Energy/Network метрики, leak trace до и после исправления.
7. Результаты холодного старта и frame timing Macrobenchmark.
8. Firebase Test Lab matrix, видео и логи.
9. Реальный GitHub Actions run и URL репозитория.

Не вписывайте фиктивные проценты, миллисекунды, статусы BUILD SUCCESSFUL или скриншоты. Для каждого задания используйте `LAB7_EVIDENCE_CHECKLIST.md`.
